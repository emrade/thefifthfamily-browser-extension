# TFF Consigliere — build design (draft)

Status: **design, nothing built.** 2026-11-20. The *what* and *why* are in
[companion-tool-plan.md](./companion-tool-plan.md); this is the *how*: project
layout, screens, data flow, and the order of work. Version 1 = card odds (incl.
teaching unknown cards) + the Avoid list with logging, on the web app and the
Discord bot.

## Two corrections to the plan (need the player's OK)

1. **The odds and verdict rules ship as code, not inside the pack.** The plan
   put a compiled "rules script" in each pack (`street_intel_packs.rules`). Running
   code fetched from the database means anyone who could write to that table
   could run code in every member's browser. Instead, the producer generates a
   TypeScript file in the tool's repository (`lib/rules/streetIntel.generated.ts`,
   compiled from the extension's `streetIntelPredict.ts` and the complication
   rule) and the pack holds **only data** plus the `rulesVersion` it was built
   for. One source of truth still holds — the file is generated from the
   extension, never edited by hand — but a rules change needs a deploy (rare:
   the formula has changed once since August). The app refuses a pack whose
   `rulesVersion` it doesn't know, so data and rules can't mismatch.
2. **Better Auth brings its own user tables.** It stores people in `user`,
   their sign-ins in `account` (provider, account id, tokens), plus `session` and
   `verification`. These replace the plan's `users` and `user_identities`: the
   plan's extra fields (`game_name`, `access_status`, `access_via`,
   `request_note`, `is_admin`, `last_seen_at`) become Better Auth "additional
   fields" on `user`. Everything else that pointed at `users.id` points at
   `user.id`. To check while building: Better Auth's `user` row expects an email,
   and Discord sign-in asks for one by default — the plan stores no emails, so
   either drop the email scope and store a placeholder, or accept storing it and
   list it on the "what we store" page.

## App layout (Next.js App Router)

```
app/
  sign-in/page.tsx                 Discord sign-in, unofficial note
  request-access/page.tsx          non-family: in-game name + note, then "waiting"
  (app)/layout.tsx                 shell: bottom bar (Home · My logs · Me), safe areas, offline banner
  (app)/page.tsx                   Home: one tile per module (opens Street Intel directly while it's the only one)
  (app)/street-intel/layout.tsx    module header + section switch [Card odds | Complications]
  (app)/street-intel/page.tsx      Card odds: type a card name → pick → condition → percentages
  (app)/street-intel/complications/page.tsx   the 24 complications: Pick/Avoid, family record, logging
  (app)/logs/page.tsx              My logs: every logged result from any module (swipe to change/remove), "log a few at once"
  (app)/me/page.tsx                in-game name, stats, calibrations, what we store, delete my data, unofficial note; admin entry for admins
  (app)/me/admin/page.tsx          admins only: requests, verdict disagreements, card reports, moderation
  api/auth/[...all]/route.ts       Better Auth
  api/street-intel/pack/route.ts           GET active pack (ETag, cached on device)
  api/street-intel/record/route.ts         GET family record + current verdict per scenario/choice
  api/street-intel/results/route.ts        POST log · PATCH change · DELETE remove (own entries)
  api/street-intel/card-reports/route.ts   POST a scouted approach of an unknown card
  api/logs/route.ts                GET my logs across modules
  api/setup/route.ts               GET/PUT member_setup (stats are game-wide; calibrations per module)
  api/admin/[...]/route.ts         decide requests, moderate, accept card reports
  api/discord/interactions/route.ts  the bot
lib/
  access.ts                        the one access check (swappable rule), used by every route
  auth.ts                          Better Auth config: Discord, guilds.members.read, additional fields
  db/schema.ts                     Drizzle schema; migrations in drizzle/
  rules/streetIntel.generated.ts   generated by the producer — never edited by hand
  rules/calibration.ts             bonus window from scouts; unknown-card role inference
  verdicts.ts                      seed vs family verdict (10 results, 3+ per choice)
  discord/                         signature check, commands, message builders, DMs
  offline/                         IndexedDB cache of pack + setup, queued logs
scripts/register-commands.ts       registers slash commands (test server + family server)
```

Every API route goes through `lib/access.ts`: session → user →
`access_status = approved`; for `access_via = family_server`, re-check
membership if the last check is over a day old (Discord's member endpoint with
the member's token, refreshed by Better Auth; with the bot installed, the bot's
own key). Bot interactions authenticate by Discord's signature and the family
server id instead of a session.

## Screens (phone first)

Navigation is **app-level, not module-level** (decided 2026-11-20): the bottom
bar never changes as modules are added; each module gets a tile on Home and its
own screen with its own sections.

```
┌──────────────────────────────┐     ┌──────────────────────────────┐
│ TFF Consigliere              │     │ ‹ Street Intel               │
│                              │     │ [ Card odds | Complications ]│
│ ┌──────────────────────────┐ │     │                              │
│ │ Street Intel             │ │     │ 🔍 Type a card name…         │
│ │ Card odds · Complications│ │     │   The Appraiser Blinks       │
│ └──────────────────────────┘ │     │                              │
│ ┌──────────────────────────┐ │     │ Condition: Dense fog ▾       │
│ │ (future module)          │ │     │                              │
│ └──────────────────────────┘ │     │ Talk ............ 65%  BEST  │
│                              │     │ Fight ........... 50%        │
│                              │     │ Run ............. 31%        │
│                              │     │ Steel yourself .. always fails│
├──────────────────────────────┤     ├──────────────────────────────┤
│  Home     My logs     Me     │     │  Home     My logs     Me     │
└──────────────────────────────┘     └──────────────────────────────┘
```

| Where | What | Key interactions |
|---|---|---|
| **Home** (bottom bar) | one tile per module; opens Street Intel directly while it's the only module | module setup to-dos show on its tile ("calibrate 2 more card types") |
| Street Intel › **Card odds** | as the phone guide: type a card name → pick → condition → each approach's percentage, best marked | condition picker (full list + search); recent cards first; "Calibrate with this scout" when the card type isn't calibrated; unknown cards: "teach us this card" with the same input |
| Street Intel › **Complications** | as the phone guide's list: all 24, each with Pick and Avoid and the family record per choice (4 choices; Stand Your Ground "not enough data yet") | search; **Pick → Won** per row (1 tap); tap a choice → bottom sheet Won / Lost (2 taps); toast with Undo · Change |
| **My logs** (bottom bar) | every logged result, any module, newest first | swipe a row: Change · Remove; "log a few at once" |
| **Me** (bottom bar) | in-game name, stats (game-wide, used by every module), calibrations per card type, what we store, delete my data, unofficial note, sign out; **Admin** for admins | number pads for stats; "Robbery ✓ 2 days ago · Leverage — not yet" |
| Me › **Admin** | pending requests, verdict disagreements, card reports, members' logs | approve/reject, accept/reject, remove |

Tablet/desktop: the bottom bar becomes a side bar; the card result sits beside
the search instead of below it.

**Adding a module later:** a tile on Home, a folder under `app/(app)/<module>/`
with its own sections, its own `api/<module>/` routes, its own `<module>_*`
tables and pack. Bottom bar, Me, My logs and the access check stay as they are.

## Data flow

- **Pack:** fetched on open with its ETag; unchanged → nothing downloaded.
  Stored in IndexedDB so lookups are instant and work offline; refused after 7
  days without a successful online check (plan decision 6).
- **Logs:** written to an IndexedDB queue first (instant on screen), sent in
  order; retried when back online. Each carries a client id so a retry can't
  log twice.
- **Setup:** `member_setup` cached on the device; edits sync with
  `updated_at`, latest wins.
- **Family record:** fetched with the pack, refreshed after each log.

## Pack producer

`scripts/consigliere/build_pack.py` (archive side, reusing the guide builder's
extraction) → `pack.json`:

```
{ "version": "2026-11-20", "rulesVersion": 1, "dataUntil": ...,
  "cards":      { "<title>": { base, category, level, legendary, approaches: [{key,label,stat,role}] } },
  "conditions": { "<sentence>": { global, stats } },
  "verdicts":   { "<scenario>": { pick, avoid: [...] } } }
```

Approach `role` is `+25 | +10 | -10 | always_fails` (bonus values only in the
rules). No counts, no stats, nothing about the player's account.

`scripts/consigliere/build_rules.ts` (esbuild) generates
`streetIntel.generated.ts` from the extension's TypeScript, then the check runs
every card × condition through both and expects 0 differences (as the phone
guide's check). Upload: insert into `street_intel_packs`, switch `is_active` in
one transaction. The `/refresh-consigliere-pack` skill wraps it; CLAUDE.md gets
one line asking Claude to offer it after archive merges and guide refreshes.

## Discord bot

One Discord application for sign-in and the bot. Endpoint
`/api/discord/interactions`: verify the Ed25519 signature → refuse anything
outside the family (or test) server → defer if the database is involved →
answer privately. Commands: `/comp`, `/avoid`, `/odds`, `/mylogs`,
`/consigliere` (plan § Discord bot). The bot links a Discord user to the same
person through Better Auth's `account` table (`providerId = discord`), creating
a user on first use if needed. Admin DMs for new requests and verdict
disagreements.

## Testing

- **Rules:** the generated rules vs the extension's predictor, every card ×
  condition, 0 differences (CI and the producer).
- **Calibration and unknown cards:** unit tests from real archived scouts (a
  small fixed sample, no personal data beyond odds), expecting the results in
  `verification/street-intel/companion/`.
- **API:** access rules (non-family refused, revoked refused, own-entry-only
  edits), rate limit, double-tap detection.
- **UI:** Playwright at phone sizes (iPhone and Android), light and dark,
  screenshots reviewed as a member would see them; then on real phones,
  installed to the home screen.
- **Bot:** a private test server before the family server.
